# Design decisions

The decisions behind the study, numbered D1–D26 as cited in the code and the other docs. Each has its resolution, the date it was fixed, and the reason.

## Research decisions

| # | Decision | Resolution | Date | Reason |
|---|---|---|---|---|
| D1 | Language scope | Python only | fixed at the outset | |
| D2 | Graph granularity | File-level nodes | fixed at the outset | |
| D3 | Edge types | Import edges only | fixed at the outset | |
| D4 | Method input | One target file | fixed at the outset | |
| D5 | Method output | Ordered list of files | fixed at the outset | |
| D6 | Objective | Reduce reading/context cost of reaching the files a change required | fixed at the outset | |
| D7 | LLM role | Evaluation only, never inside the method | fixed at the outset | |
| D8 | Human study | Out of scope | fixed at the outset | |
| D9 | Graph builder + graph construction rules | Custom `ast` builder (`src/depgraphs/graph/ast_builder.py`). Rules: `import a.b.c` → edge to the deepest existing module only, no extra edges to parent `__init__` (parent_inits=False); `from pkg import name` → `pkg.name` if it is a module, else `pkg/__init__.py` (as written, no re-export chasing); repeated imports count once (unweighted); `TYPE_CHECKING` and function-level imports kept; `.py` files not importable by name are not nodes (counted); test files are not nodes (D18) | 2026-09-22 | On all 4 comparison repos it gave exactly grimp's and tree-sitter's edges (independent tools), while also covering files outside packages and counting every unresolved import construct; "as written" rules keep the graph to imports actually typed, with no inferred edges |
| D10 | Repository sample (rules R1–R5, K, strata, n, seed) | K=10; R2/R3 variant b; take every repo that passes (no draw of repos); at most 20 tasks (PRs) per repo, drawn by seed; domain list fixed before labelling (web/API, scientific/numeric, data/ML, developer tools/testing, CLI/infrastructure, other); archived and monorepo-flagged repos kept (no rule excludes them) | 2026-09-22 | RQ2 needs as many repos as possible (power table); variant b counts stubs/Cython as Python and `test/` as a test folder, which is what the rules are for; the 20-task cap keeps every repo but cuts test-box downloads by ~65% |
| D11 | Task source | D: SWE-bench as a fixed comparability block + SWE-bench-Live + SWE-rebench | 2026-09-22 | Only option giving RQ2 ~100 repos while keeping a SWE-bench block; newer tasks usable in the downstream experiment |
| D12 | Primary vs validation key sources | Primary key = union of co-edited + symbol + execution (D20 rule B). Every result is also reported per source. If the execution run does not cover all PRs, the primary key for the uncovered PRs is co-edited + symbol, and the execution source is reported on its (random) subset only | 2026-09-22 | Three independent kinds of evidence; symbol overlaps the import graph by construction, so per-source reporting is mandatory |
| D13 | Cost unit, budget grid, seed cost | Primary cost = physical lines of each listed file. Secondary: files, and tokens (tiktoken `o200k_base`). Budget grid (lines) = 250, 500, 1k, 2k, 4k, 8k, 16k, 32k; AUC = mean coverage over the grid (equal weight per doubling). Seed's own cost is not counted (same for all methods; the seed is never in a list) | 2026-09-22 | Lines are model-independent and simple; a doubling grid covers small and huge repos with one scale |
| D14 | Statistical tests, effect sizes, correction | Unit = PR (tasks averaged within PR). Each method vs random floor and pairwise between methods: Wilcoxon signed-rank + Vargha–Delaney A12, Holm correction within each family. All methods over repos: Friedman + Nemenyi on per-repo means. RQ2: Spearman per pre-listed (Table 1 metric, method) pair across repos, Benjamini–Hochberg, labelled exploratory, every pair reported. 95% CIs by bootstrap resampling repos (2,000 resamples, seed 20260922) | 2026-09-22 | Standard for paired, non-normal SE data (Demšar 2006; Arcuri & Briand 2014) |
| D15 | Model, repetitions, budget, spend (downstream experiment) | Not run; the downstream experiment is specified in the paper's appendix, not conducted | | |
| D16 | Which RQs are in this paper | RQ1–RQ4 in; RQ5 in only if the downstream-experiment budget is approved (it was not run, see D15); RQ6 deferred | 2026-09-22 | RQ1–RQ4 stand alone and cost nothing; RQ5 is the practical check; RQ6 needs separate proof checking |
| D17 | Graph per task commit vs one pinned commit | One graph per task base commit (cached by commit). Table 1 at the pinned SHA, plus a summary across task commits | 2026-09-22 | Correctness (files must exist at the task's commit); cheap: 94% of tasks have their own commit and a graph takes 0.1–30 s |
| D18 | Role of test files | Study test rule = path rule (`tests/`, `testing/`, `test_*.py`, `*_test.py`, `conftest.py`) + folders named `test` (`is_test_path`). Test files are not graph nodes, cannot be seeds, and are never in the answer key; the file-count filter counts non-test files only | 2026-09-22 | The task is changing source files; SWE-bench-style datasets already separate tests into `test_patch`; one rule used everywhere |
| D19 | File-count filter (2–10 vs 1–10), line cap, what the cap counts | 1–10 non-test `.py` files; single-file and multi-file tasks reported separately everywhere; cap 200 changed lines, counted on non-test `.py` files only | 2026-09-22 | 66% of usable tasks are single-file and still have symbol + execution keys; the cap changes counts by only 1–4%; the cap is counted on the same non-test `.py` files as the filter |
| D20 | What counts as "executed" | Primary B: a file counts if a line inside a function/method body ran during a fail-to-pass test. Sensitivity C: B minus files that run in a do-nothing test. A (any line) reported only to show the effect of import-time noise | 2026-09-22 | B removes import-time noise; C additionally removes framework/fixture noise; both are measured |
| D21 | Tie-breaking and within-clump order | Random with a fixed seed, averaged over 5 seeds (20260922+i, i=0..4), for every method | 2026-09-22 | Cannot favour any directory layout; cheap without a model |
| D22 | Adaptation specs (BM25, co-change, published approaches) | Written in `docs/methods.md` before any run | 2026-09-22 | Structure-only adaptations, never compared to published numbers |
| D23 | Embedding model | `jinaai/jina-embeddings-v2-base-code`, revision `516f4baf13dec4ddddda8631e019b5737c8bc250`, **first 512 tokens** of each file, L2-normalised, cosine similarity; run on CPU. Revised before any run | 2026-09-22 | First choice was the full 8,192-token window; measured 0.28 files/s on CPU = ~120 h for 124,767 unique file versions. 512 tokens measured 3.96 files/s = ~9 h. Changed before any method ran |
| D24 | How the design freeze is recorded | Written down in `docs/metrics.md` and `docs/methods.md` on 2026-09-22; no external registry | 2026-09-22 | No OSF account |
| D26 | Wrong-seed sampling rule | For d = 1, 2: uniform random among graph files at undirected distance exactly d from the true seed (seeded by SHA-256 of 20260922+task_id); if none exist, the task is counted as 'no file at distance d' for that condition. Random condition: uniform over all graph files except the true seed | 2026-09-22 | RQ4 wrong-seed definition: pick uniformly at random, with a fixed seed, among files at exactly distance d (ignoring direction) from the true seed |

Sampling seed for D10: **20260922**. Set mechanically as the date (YYYYMMDD), before the draw ran, so it was not chosen by looking at outcomes.

## Implementation choices

| Date | Choice | Why | What it affects |
|---|---|---|---|
| 2026-09-22 | Python 3.12 (uv-managed), dependencies pinned in `uv.lock` | Widest library support among current Pythons | Nothing in the research design |
| 2026-09-22 | Entry point is `python run.py all` (plus a `Makefile` that calls it) | `make` is not available on every machine | Nothing in the research design |
| 2026-09-22 | Datasets pinned to Hugging Face revisions recorded in `src/depgraphs/datasets.py` and checksummed in `data/datasets/MANIFEST.json` | Reproducibility | All counts |
| 2026-09-22 | Downloaded SWE-rebench `filtered` split only, not the ~21k-task full split | `filtered` is the split with prebuilt images for every task | Pool of fresh repos; the full split could be added |
| 2026-09-22 | Task-eligibility recount counts the line cap on the source patch only. This differs from how the earlier provisional counts were computed | Counts are recomputed from the data, not copied | Eligible counts; see D19 |
| 2026-09-22 | Candidate pool for the sample = repos with ≥10 eligible tasks under the widest option (1–10 files, 200-line cap), R1 datasets only, after duplicate-task removal. Narrower options are subsets | So every option has real numbers behind it | Only what is measured; nothing is selected |
| 2026-09-22 | R2/R3 measured at a **provisional** snapshot = base commit of each repo's newest eligible task (Pro: newest by commit date) | R2/R3 need a snapshot to measure; D10 pins the real one | Only the R2/R3 numbers in `data/candidates.csv` |
| 2026-09-22 | R2 definition used for measuring: Python code lines ÷ code lines in a fixed list of programming-language extensions (`CODE_EXT` in `candidates.py`), non-test and non-vendored files only, counted with pygount 3.2.0 | R2 needs one fixed tool, recorded | R2 outcome per repo |
| 2026-09-22 | The custom `ast` builder has one switch per open graph-construction rule. The "parent inits" switch covers `from a.b import x` as well as `import a.b.c`, because Python runs parent `__init__.py` files for both. Default switch values are placeholders for tests only — D9 sets the real ones | Seen on anyio: pydeps' extra edges were all parent `__init__` edges from from-imports; a switch limited to `import a.b.c` would have done nothing there | Only the builder comparison numbers |
| 2026-09-22 | Builder comparison repos chosen by rule: the passing repo with fewest non-test `.py` files from SWE-bench (pytest-dev/pytest, 89) and from the other datasets (cekit/cekit, 50; tie with django-rest-framework-json-api broken by name). seaborn and django-rest-framework-json-api were also run; their results are kept and labelled as extras, not deleted | Picks by rule, not by judgement | Only the builder comparison numbers |
| 2026-09-22 | R2 "variant b" measured alongside the rule as written (`.pyi/.pyx/.pxd/.pxi` count as Python; `test/` is a test folder; `cextern` is vendored). Adopted in D10 | Several R2 failures came from definitions, not from non-Python code (mypy stubs, sqlfluff `.sql` test fixtures, astropy bundled C) | Which repos pass R2/R3 (7 flips) |
| 2026-09-22 | Graph discovery: `.py` files that cannot be imported by name (folders like `my-example/`), hidden folders, duplicate module names are not nodes and are **counted** per reason | Every Python import construct is handled or counted; never dropped silently | Node counts; D9 keeps this |
| 2026-09-22 | "Vendored" = any path directory in {vendor, vendored, _vendor, third_party, thirdparty, 3rdparty, extern, externals, external}; "generated" = a marker (generated by / do not edit / autogenerated / @generated) in a file's first 5 lines | Needs a mechanical rule for the 30% exclusion | Exclusion flag only |
| 2026-09-23 | New study arm (`study2`): compare import-graph proximity against issue-text retrieval as reading orders, and report per evidence source instead of a union | The union key is dominated by the symbol key (7,675 vs 4,458 file references), so a single headline number hides the reversal that is the actual finding | Replaces the union-key bake-off as the paper's spine; the union-key study is not part of the replication package |
| 2026-09-23 | Issue text taken from the `problem_statement` field of the source benchmark rows, tokenised with the same identifier splitter used for file contents | Matched for all 1,873 instances; one vocabulary means text and code are comparable without a model | Enables the whole lexical family; nothing existing changes |
| 2026-09-23 | Execution-based key excluded from this study rather than estimated from the ~113 PRs that have it | Too small a subset to rank 19 methods on; reporting it would invite a comparison the data cannot support | Study has two evidence sources, not three; flagged in the paper as the natural third leg |
| 2026-09-23 | Cost-scaled (`_pl`) variants and a `path_seed` control added alongside the main methods | The metric charges by lines, so 'prefers short files' and 'ranks the right files' must be separable; `path_seed` separates 'issue text' from 'path proximity' | Two extra columns per table; `path_seed` shows the lexical gain is attributable to the issue text on the co-edited key only |
| 2026-09-23 | Ties re-drawn 3 times per task, not 5 as in the first study arm | Score-based orderings have almost no ties; 3 runs keeps the full sweep under 10 minutes | Only the tie-break averaging; noted in the paper |
